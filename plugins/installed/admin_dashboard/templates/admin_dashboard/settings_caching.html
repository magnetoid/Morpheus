{# ── 2. BROWSER + EDGE CACHE-CONTROL HEADERS ─────────────────────── #}
{% csrf_token %}

Browser + edge Cache-Control

Headers Django emits on every response. Cloudflare reads s-maxage for its edge; browsers honour max-age.

For anonymous storefront pages. 2026 baseline: public, max-age=0, s-maxage=300, must-revalidate, stale-while-revalidate=86400, stale-if-error=86400 — browser revalidates every load, edge holds 5 min, serves stale for a day on origin failure.

/static/ + /media/. 31536000 = 1 year (standard with hashed filenames).

Anonymous /graphql/ read queries emit s-maxage=N + per-entity Cache-Tag (e.g. product:hamlet) so CF caches them AND auto-purge can target a single product. Mutations + authed calls stay no-store. Biggest win for headless storefronts.

{# ── 4. RESOURCE HINTS ───────────────────────────────────────────── #}
{% csrf_token %}

Resource hints

<link rel="preconnect|dns-prefetch"> tags emitted in <head>. Tells the browser to warm up critical connections before they're needed.

Full handshake (DNS + TCP + TLS) warmed before the asset is needed. Use for 1-3 most critical third-party origins.
Example: https://www.googletagmanager.com, https://fonts.googleapis.com

DNS-only warm-up. Cheaper than preconnect; use for less-critical third parties (Stripe, Intercom, optional analytics).

Service worker / PWA

Caches static assets in the browser's installable storage, serves them offline, makes repeat visits load instantly.

Shown when the network is down and the page isn't in the worker cache.

Per-route cache TTLs

Override s-maxage per route type. Home and category lists change rarely → cache longer. Search results are user-specific → short or off.

{# ── 7. COMPRESSION ──────────────────────────────────────────────── #}
{% csrf_token %}

Compression

Origin-side response compression. Cloudflare also compresses at the edge, but origin compression saves bytes on the CF↔origin hop AND keeps things compressed for clients that bypass CF.

Skip compression for responses below this size — the CPU cost outweighs the wire savings. 1024 (1 KB) is the standard threshold.

{# ── 8. CRITICAL CSS + FONT LOADING ─────────────────────────────── #}
{% csrf_token %}

Critical CSS + fonts

Strategies that shave seconds off First Contentful Paint. The biggest LCP / FCP wins come from controlling what blocks the first render.

CSS font-display property. swap shows fallback text immediately, swaps when web font loads (no invisible text). optional uses fallback if font isn't ready in 100ms (best for performance, worst for design fidelity). block waits up to 3s before showing fallback.

Emits <link rel="preload" as="font" type="font/woff2" crossorigin>. Use for the 1-2 critical font files only — preloading too many slows everything down.

{# ── 9. CACHE WARMING ────────────────────────────────────────────── #}
{% csrf_token %}

Cache warming

After a deploy or purge, the cache is cold — the first visitor pays for the slow render. Warming pre-fetches the most popular pages so customers always hit a warm cache.

Ranked by last-7-day analytics. 20 is a safe default; 100+ noticeably slows the deploy.

Pages that aren't in the top-N but you always want warm — campaign landing pages, checkout, login.
