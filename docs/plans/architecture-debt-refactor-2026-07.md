# Architecture Debt Refactor — core->plugin decoupling + disable-safety

## Context

**Why now.** ADR 0017 (superseding ADR 0010's "tiny core") says the kernel stays *a clean set of extension points* — the mechanism that keeps a deliberately powerful platform swap-able, disable-safe, and agent-legible. Two enforcement gates already encode this, and both are currently carrying debt:

1. **The core-boundary ratchet** (`scripts/check_core_boundary.py` + `scripts/core_boundary_baseline.json`, run as CI, pre-commit, and a PostToolUse hook). It AST-walks every non-test file under `core/`, collects each `from/import plugins.installed.*` as a `(relative_path, dotted_module)` pair, and compares against the allowlist. Enforcement is **two-way**: a pair *not* in the baseline (a new leak) fails the build, **and** a baseline pair no longer found on disk (a stale row) *also* fails. The allowlist can therefore only **shrink**, and every refactor phase must delete its cleared rows *in the same commit*. Authoritative current state: **22 allowlisted `(file, module)` pairs** (30 lazy import statements) across **9 core files**; the on-disk scan matches the baseline exactly, no bypass.

2. **The two disable litmus tests.** (a) *Delete* `plugins/installed/<name>/` → the feature is gone with no dangling import. (b) *Disable* the plugin → **every** surface it added disappears. Guarded by `admin_dashboard/tests/test_disable_guards.py` (hardcoded nav links must sit behind `{% plugin_enabled %}`) and `core/tests/test_hook_disable_gating.py` (`fire`/`filter` skip handlers whose owning plugin is inactive). A surface a *shared shell* hard-imports bypasses the bus and survives a disable — the ADR 0023 bug class.

Every leak below is a **lazy, try/except-guarded import** — architectural debt, not a runtime crash. The goal is to invert each one so the plugin *contributes* through a mechanism instead of the kernel *reaching in*, driving the baseline to **0** and closing the named disable-leaks — without regressing behavior.

### Completeness pass — debt / gaps the audits under-surfaced

1. **No ratchet covers *plugin -> plugin* shell coupling.** `check_core_boundary.py` scans only `core/`. `admin_dashboard`/`storefront`/`themes` hard-importing an optional plugin is exactly how bookvault and cloudflare leaked, and *nothing prevents the next one* — the disable-test suite only checks nav links + hook gating, not arbitrary view imports. **Recommendation (folded into Phase 6):** extend `check_core_boundary.py` (or a sibling guard) to also scan the shared-shell plugins for imports of *optional* (non-foundational) plugins, with its own shrink-only baseline. Without this, Phases 4-6 fix today's leaks but leave the class open.
2. **Baseline pairs are per `(file, module)`.** A pair clears only when **every** import site of that module in that file is removed. `ecommerce_writes.py` imports 5 modules across ~10 sites — moving `orders.update_status` alone does *not* shrink the baseline; all three orders tools must move together. This dictates the phase groupings below.
3. **`register_tool` is keyed by `tool.name`** (`core/agents/registry.py:43`) — a second registration silently overwrites. The `_migrated_names` + plugin-side registration must not double-register (acute for the `orders.refund` name-collision). Add a test asserting each migrated name is registered exactly once and owned by the plugin.
4. **`capabilities.py:96` is a SECOND consumer** of `contribute_agent_tools()` (dashboard capability list). Verify moved tools appear there correctly and are not duplicated.
5. **`plugins/context_processors.py:plugin_context` already exists** as an aggregator — Phase 8's context-processor consumer should extend it, not add a parallel one.
6. **Marketing coupons** (`views_split/marketing.py` imports `marketing.models.Coupon`) — audit flagged it "not a nav leak" but did **not** confirm URL ownership. If the URL is registered in `admin_dashboard` (not `marketing.register_urls`), the view still leaks on disable. Verify during the Phase 6 shell-sweep.
7. **Do NOT chase confirmed non-leaks:** `product_videos` card is inside a `display:none` legacy wrapper (`product_form.html:1274-1335`); storefront account sub-pages (`account.py` orders/returns/addresses) query **foundational** `orders`/`customers` (never disabled); downloads/credits are already resolved. CLAUDE.md's "Known debt to repay" paragraph is **stale** — correct it (Phase 4).

## Prerequisites to build first (must-build mechanisms)

No must-build mechanism gates a *different* cluster — each new primitive serves only the cluster it ships with, so there is **no forced mechanisms-only phase**; each phase builds its mechanism as item #1 and consumes it in the same commit (a mechanism shipped with no consumer would be a latent no-op — exactly the trap `register_context_processor` is today).

- **`AGENT_APPROVAL_AUDIT` fire-and-forget hook** in `core/hooks.py` — so the shared `_require_hard_gate` helper (`ecommerce_writes.py:111`) sheds its `agent_core.models` import; agent_core subscribes and writes the row. *Small.* (Phase 2)
- **`contribute_agent_tools()` plumbing for workflows** — `plugins/installed/workflows/agent_tools.py` + `contribute_agent_tools()` in `app.py` + `tests/test_agent_tools.py`, mirroring catalog/orders. Only target plugin lacking it. *Small, greenfield.* (Phase 3)
- **`PRODUCT_LIST_COLUMNS` filter** in `core/hooks.py` MorpheusEvents + fire site in `admin_dashboard/views_split/products.py:52` + generic per-row column loop in `products.html`. Near-clone of `PRODUCT_FORM_CARDS`, but the column dict must carry a **`product_id -> cell` map** (cells are per-row, unlike single-object form cards). *Small.* (Phase 5)
- **`AGENT_SYSTEM_PROMPT` / `SYSTEM_PROMPT_PREFIX` filter** in `core/hooks.py` (absent — grep for `SYSTEM_PROMPT`/`BRAND_VOICE` is empty). Retires both brand-voice sites. *Small.* (Phase 7)
- **`BRAIN_SIGNALS` filter** in `core/hooks.py` + fire site in `core/brain/signals.py`; **plus** promote the private `seo.views._cwv_summary` (`seo/views.py:504`) to a public `seo.services` API *first* (most fragile import in the set — silent break under `suppress(Exception)`). *Medium.* (Phase 8)
- **`register_context_processor` CONSUMER** — a public `app_registry.context_processors()` accessor that records the owning plugin, **plus** a single request-time aggregator context processor (extend `plugins/context_processors.py:plugin_context`) registered by dotted string in `morph/settings.py` that iterates the accessor, merges dicts, and **skips funcs whose owning plugin is inactive** (context processors are NOT bus-gated, so replicate `core/hooks.py:63 _owner_inactive`; `add_context_processor` at `registry.py:424` must also record the plugin name). *Medium.* (Phase 8/context)
- **Shell-plugin boundary guard** (completeness #1) — extend the ratchet to cover `admin_dashboard`/`storefront` importing optional plugins, own shrink-only baseline. *Small-medium.* (Phase 6)
- **agent_core Worker-runtime service facade + an ADR** on whether agent run-state (`AgentRun`/`AgentStep`) is core or plugin. `contribute_agent_tools` is the wrong mechanism (kernel orchestration, not domain tools). *Large + design decision.* (Phase 10)
- **REUSE (no build):** `_require_hard_gate` should be exposed as an importable core helper (plugin -> core, correct direction) so plugin-owned hard-gated tools call it. `contribute_agent_tools()` + `_migrated_names` and the `core.hooks` bus (`register`/`fire`/`filter` with `_owner_inactive` gating) are live and production-proven; `PRODUCT_FORM_CARDS`, `ACCOUNT_SUMMARY_FIELDS`, `EMAIL_TEMPLATE_OVERRIDE` are the reference fire/subscribe templates.

Band C (Phases 7-10) builds the new core mechanisms cheap -> expensive, ending on the genuinely hard Worker-runtime extraction. Baseline trajectory: **22 → 15 → 12 → 10 → (10) → 8 → 2 → 1 → 0.**

## Risks & landmines

- **The core-boundary ratchet is two-way.** Every baseline phase MUST delete its cleared rows from `scripts/core_boundary_baseline.json` **in the same commit** as the import removal, or CI goes red on a stale row even though the code is correct. Verify with the guard itself; **never** `--save` to paper over a move. A `(file, module)` pair clears only when *every* import site of that module in that file is gone (completeness #2).
- **Merging to `main` IS a production deploy** (Coolify watches the repo). Ship one phase per deploy; batch local commits; do NOT land phases in rapid succession (thrash -> `ERR_CONNECTION_RESET`). Smoke the live URL — especially Phase 8b (fires every request) and Phase 10 (Linda's delegate loop). Native-dep 503 window doesn't apply (no new deps) — but confirm via Coolify app-logs, don't panic-rollback a build gap.
- **sqlite hides Postgres migration crashes.** These phases move Python tool/hook code and add **no models**, so migration risk is low — but if any phase incidentally adds a model, trust CI's real-Postgres `migrations` job, not a green sqlite run; cross-type FK retargets must be `RemoveField`+`AddField`.
- **Do not break the agent runtime when moving tools.** `spawn.py` is imported eagerly; `capabilities.py:96` is a second `contribute_agent_tools()` consumer; `register_tool` overwrites on name collision (`orders.refund`). Reconcile refund hard-gate parity before deleting core's copy; keep `core.safety 'pricing_change'` reachable.
- **Hook-disable-gating is the safety net for contributed surfaces, not for shell hard-imports.** A surface a shared shell hard-imports (bookvault, cloudflare) bypasses `_owner_inactive` entirely — that's why the disable-leaks need the hook/panel migration (Phases 4-6), not just a `try/except`. `try/except ImportError` guards *absence*, not *disable*.
- **Silent-failure debt.** Brain signals, brand voice, and the hard-gate audit are wrapped in `suppress(Exception)` / `except: pass` today — a broken migration to the new mechanism fails **silently** (blank panel, lost audit row). Every such phase needs an explicit **behavior-parity** test, not "does not raise."
- **Ruff version drift.** Verify changed files with **local ruff matching CI (0.15.8)**, not the lenient pre-commit (0.7.4) — a green pre-commit is not enough.
- **Living-document rule.** Same-commit doc updates: the ADR 0023 landmine paragraph (Phases 4-5), the "still leaking" `cart_context` claim (Phase 8b), the stale "Known debt to repay" paragraph (Phase 4), new hook constants documented in `core/hooks.py` + `docs/PLUGIN_DEVELOPMENT.md`/`docs/ARCHITECTURE.md` (Phases 5, 7, 8, plus the shell guard in Phase 6), and the agent run-state ADR (Phase 10). An undocumented new mechanism becomes the next latent trap — exactly what `register_context_processor` is today.
- **Scope discipline.** Do NOT chase the confirmed non-leaks (completeness #7): `product_videos` `display:none` card, storefront account sub-pages (foundational `orders`/`customers`, never disabled), downloads/credits (resolved). Each wasted phase is a wasted deploy.

## Verification strategy

**Prove behavior preserved.** Every port is behavior-preserving, so the bar is: (1) a **per-target unit test** the moved tool/handler/processor produces the same output (golden/snapshot where an aggregator is involved — brain signals, nav cart count); (2) a **contract test against the real interface** for money/runtime paths (refund echo hard-gate, `AgentRun` persistence, `pricing_change` blocklist), never a mock, per the AI-code-verification rule; (3) an **exercised** test for every `suppress`/`except: pass` path so a silent regression can't hide.

**Prove disable-safety.** For each migrated surface, extend `core/tests/test_hook_disable_gating.py` / `admin_dashboard/tests/test_disable_guards.py` to assert the surface (tool, card, column, panel, context key) is present when the owning plugin is active and **absent when deactivated-while-configured** — the disabled-but-configured state is the one the current config/data-presence gates get wrong.

**Prove the baseline shrank.** Run `python scripts/check_core_boundary.py` after each phase; it is green only if the code removed the imports **and** the commit deleted the matching baseline rows. Trajectory, asserted per phase: **22 -> 15 (P1) -> 12 (P2) -> 10 (P3) -> [10 through P4-6] -> 8 (P7) -> 2 (P8a) -> 1 (P8b) -> 0 (P10).** Phases 4-6 add a *second* shrink-only baseline (the shell-boundary guard) that likewise only decreases. Baseline 0 means `check_core_boundary.py` allows an empty allowlist — the ratchet is fully paid.

**Full suite each phase:** `DATABASE_URL='sqlite:///:memory:' python manage.py test` (scoped to touched plugins during iteration, full run before the deploy), plus `python manage.py check` (blocking on model-relation errors that 503 prod) and `makemigrations --check --dry-run`. Then smoke the live URL for anything on a hot path (Phase 8b every-request cart count; Phase 10 a real delegated run on the compose stack, since `.delay()` only fires eagerly under tests).
